<objective>
Fix the long-message silent-drop bug in the Slack and WhatsApp channel adapters — the
same bug class already fixed for Telegram (#20). Both adapters currently do a single
unguarded send: WhatsApp sends one `sendMessage`, Slack posts one `chat.postMessage`.
When a reply exceeds the channel's limits (WhatsApp ~65536 chars; Slack 3000/2000/50
block limits) the platform rejects or truncates and the user silently loses the reply.

Slack is the real risk because it is block-aware: a section block's mrkdwn `text` is
capped at 3000 chars, a section's `fields[]` is capped at 10 fields (each ≤2000 chars),
and a message carries ≤50 blocks. The fix must split/normalize blocks against all three
limits AND preserve the byte-identical single-call payload for normal short messages.

Purpose: agents' long replies (code blocks, tables, multi-section text) reach the user in
full on Slack and WhatsApp, matching the Telegram fix.

Output: new `src/channels/slack/split.ts` (+ tests), exported block types from
`table-formatter.ts`, wired `send()` in both adapters, CHANGELOG entry.
</objective>
