<objective>
Pre-transcribe inbound voice/audio attachments at the shared ingestion boundary so chat-channel voice notes (Discord/Telegram/Slack/WhatsApp/Zoho) reach the head as plain text immediately — eliminating the per-message latency of the head choosing to spawn an async `audio-transcribe` sub-agent (issue #9).

Purpose: The voice WebSocket channel already transcribes synchronously at its adapter boundary (`transcribeWav` in src/channels/voice/adapter.ts handleAudio). This applies that proven pattern to chat-channel audio — in ONE shared place (`headRouteMessage` in src/index.ts) so all four channels and any future channel benefit without per-adapter duplication.

Output: A general `transcribeAudio()` Whisper helper, a pure/testable `transcribeInboundAudio()` ingestion helper, wiring in `headRouteMessage`, and unit tests for both the helper and the ingestion behavior.
</objective>

<investigation_findings>
<!-- Confirmed by reading the codebase before this plan was written. -->
- All chat adapters (Discord, Telegram, Slack, WhatsApp, Zoho) download audio to disk under {workspacePath}/media/ and set `att.path`; NONE provide an in-memory buffer (the Attachment type has no buffer field). The no-mediaDir branch sets `att.url` instead. So `transcribeInboundAudio` reads the buffer from `att.path` (fs.readFileSync), and falls back to fetching `att.url` only when there is no path. If neither path nor url is present, skip that attachment (keep it as-is).
- `headRouteMessage` is currently synchronous (returns void) and every adapter caller ignores its return value (`this.handler({...})`), so it can be made `async`/do internal `await` safely — no caller signature changes needed. The handler must `await` the transcription BEFORE `headQueue.enqueue` so the head sees text on the first turn.
- Whisper's API accepts mp3/mp4/mpeg/mpga/m4a/wav/webm/ogg directly. NO ffmpeg, NO RIFF parsing, NO 0.5s WAV gate (that gate is specific to the live-mic stream; deliberate chat voice notes don't need it).
- The voice adapter has a 10 MB oversize drop (MAX_WAV_BYTES). Whisper's own hard limit is 25 MB. Apply a defensive size ceiling in `transcribeAudio` (or in the ingestion helper) so an oversized file degrades gracefully instead of erroring out the SDK call — treat oversize as a failure → fall back.
</investigation_findings>
