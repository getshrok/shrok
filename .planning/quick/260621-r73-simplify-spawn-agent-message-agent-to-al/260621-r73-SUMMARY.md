# Phase quick-260621-r73 Plan 01: Simplify spawn_agent / message_agent to all-in-one delivery Summary

Reversed issue #45's "verbatim context pass-through" machinery. `spawn_agent` now takes a single rich `task` (no `context`) and `message_agent` a single all-in-one `message` (no `context`); the head's text is delivered to the sub-agent directly with no LLM composer/classifier in between. Deleted the composer + classifier modules, removed the `agentContextComposer`/`snapshotTokenBudget` config knobs from backend and dashboard, kept all behavioral stewards intact, and bumped to 0.7.0.

## What shipped

- **spawn_agent**: required params collapsed to `['description','task','name']` (+`'model'` in dynamic mode). `task` description rewritten to a soft "all-in-one request, relay verbatim where it matters, say what not how" framing. Dispatch dropped the `context` spread.
- **message_agent**: required params collapsed to `['agentId','message']`. `message` is now the delivered turn — the three steward calls (`runMessageAgentSteward` running/completed + `runResumeSteward` suspended) read `message`; the composer block was removed and `deliveredBody` is the head's `message` directly.
- **spawn path (local.ts)**: composer block removed; `agentFirstMessage` collapsed to `task` (+ optional `context` fallback appended). `composeVerbatimContext` import gone.
- **SYSTEM.md**: delegation directives reworded from the two-part `context`+`task` / "relay don't author" contract to the all-in-one `task`/`message` contract.
- **Config cleanup**: `agentContextComposer` + `snapshotTokenBudget` removed from `config.ts`, `system.ts`, `index.ts`, `local.ts`, `head/index.ts`, the settings route + CONFIG_JSON_FIELDS, and the dashboard Settings Experimental tab (toggle + budget input), draft state, and api types.
- **Stewards intact**: `runMessageAgentSteward`, `runResumeSteward`, `runSpawnAgentSteward`, and the post-activation spawn/action-compliance gates are unchanged in behavior — only the source field the message_agent stewards read changed (`context` → `message`).

## Deviations from Plan

### Auto-added/auto-fixed

**1. [Rule 2 — Missing critical correctness] SYSTEM.md delegation rewording**
- **Found during:** Task 1
- **Issue:** The default system prompt (`src/identity/defaults/SYSTEM.md`) instructed the head to paste into a `context` param and described the old two-part contract — a param that no longer exists. Left unchanged, the model would be told to use a removed field.
- **Fix:** Reworded the Delegation section + the suspended-agent reply instruction to the all-in-one `task`/`message` contract.
- **Files:** src/identity/defaults/SYSTEM.md (committed in Task 1, b2f790d). No test asserts on that text.

**2. [Rule 3 — Blocking build issue] Composer eval scenarios + harness plumbing**
- **Found during:** Task 2 (whole-repo grep after backend/dashboard cleanup)
- **Issue:** `scripts/` is inside `tsconfig.json` `include`, and `scripts/eval/scenarios/composer-multi-task.ts` + `composer-context-carry.ts` (plus `harness.ts` plumbing) referenced the deleted `composeVerbatimContext` flow and passed the removed `agentContextComposer` knob into `buildSystem`/`LocalAgentRunner` options — both of which would break `npx tsc --noEmit` and the CI `lint` job.
- **Fix:** Deleted the two composer scenario files, removed their imports/registration in `scripts/eval/run.ts`, removed their `package.json` eval scripts, and stripped the `agentContextComposer` param/options-fields/spreads from `scripts/eval/harness.ts` (`makeLocalAgentRunner` had no remaining callers).
- **Files:** scripts/eval/run.ts, scripts/eval/harness.ts, package.json, deleted composer scenarios (committed in Task 2, 595966e).

### Deferred (left intact, no live consumer broken)

- `SpawnOptions.headHistory` (src/types/agent.ts) and `HeadToolExecutorOptions.getHistory?` + the activation.ts `getHistory` wiring remain. After the composer removal nothing reads `headHistory`, but per the plan its full removal was deferred to keep the change focused; they're harmless (the option is still passed but unused by the composer-free path). `getRecentTurns?` (executor option) WAS removed since it had a single dead consumer.
