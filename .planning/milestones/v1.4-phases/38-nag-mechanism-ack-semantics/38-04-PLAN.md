## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan | Severity |
|-----------|----------|-----------|-------------|-----------------|----------|
| T-38-08 | Tampering | Model calls acknowledge_reminder on an ordinary reminder to silence it | mitigate | D-08 two-layer: (a) airtight HEAD_TOOLS description scoping to requiresAck-only; (b) server-side hard error when `requiresAck===false`. Tests 3 pins the server-side defense | medium |
| T-38-09 | Tampering | Model calls acknowledge_reminder on a task to disable it | mitigate | Server-side `schedule.kind !== 'reminder'` hard error (Pitfall 5); Test 4 pins it | medium |
| T-38-10 | Repudiation | Model acks before the user confirms | mitigate | Description requires "only when the user has explicitly confirmed" (D-08 model-facing); plus the in-event instruction from Plan 03 conditions ack on user confirmation | medium |
| T-38-11 | Denial of Service | Stale/double ack surfaces confusing "failed to acknowledge" errors | mitigate | D-09 benign no-op for not-found and ackPending===false; Tests 5/6 pin `{ ok: true }`. Hard error reserved for the requiresAck===false misfire only | low |
| T-38-12 | Information disclosure (V5) | reminderId injection into store path | accept | reminderId is a schedule id string; file-store keys by filename = id, no path traversal in store API; ids are generated, not user-authored | low |
