    3. NO-DELIVERY-SET REGRESSION: spawn with `headId:'a'` and NO `deliverToHeadIds` (omit the key); assert exactly ONE `agent_completed` row, head_id === 'a' (byte-equivalent to pre-Phase-44 single-head).

    4. QUESTION-SUPPRESSION (D-06): spawn with `trigger:'scheduled'`, using an LLM stub whose completion-steward response is `makeStewardQuestionResponse(...)` (classifies output as 'question'); `awaitAll`; assert `waitForStatus(agentStore, agentId, 'completed', ...)` succeeds (status is 'completed', NOT 'suspended') — i.e. the scheduled agent force-completed instead of suspending. Optionally also assert an `agent_completed` event exists and NO `agent_question` event exists for that agentId.

    5. AGENT_FAILED OWNER-ONLY (D-05): spawn a scheduled agent that fails (model the failure stub on the analog's agent_failed test at ~340), with `headId:'a', deliverToHeadIds:['b']`; assert there is exactly ONE `agent_failed` row for that agentId and its head_id === 'a' (owner); assert NO `agent_failed` row has head_id === 'b'.

    Use the analog's polling helpers and direct `db.prepare(...).all()/.get()` for multi-row/count assertions. Keep timeouts in line with the analog (2000-3000ms). No `vitest --watch` flags.
