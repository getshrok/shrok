| Boundary | Description |
|----------|-------------|
| SSE event → client filter | shouldDeliverStreamEvent is the single chokepoint deciding whether a per-head event reaches the caches; a fail-open default here is the core cross-head-disclosure threat. |
| selectedHead → React Query cache key | The head component on each cache key isolates one head's accumulated activity from another's; a flat (non-head-keyed) cache would interleave heads. |

| T-50-07 | Information Disclosure | SSE event missing/under-resolved headId falling through the filter (fail-open) | mitigate | The filter is fail-closed AND per-type: each of the six per-head types resolves headId via its correct path (top-level event.headId for five, (event.payload as StewardRun).headId for steward_run_added) and a non-matching or absent value returns false (drop). A blanket cast is explicitly rejected because it would read undefined for steward_run_added and silently drop every steward run for every head. selectedHead===null is the only deliver-all path and exists only during pre-resolution initial render (no head selected yet, so no cross-head context to leak into). | T-50-08 | Information Disclosure | stale cross-head items lingering after head switch | mitigate | D-03 reset effects clear each live accumulator on [selectedHead]; head-keyed backfill keys force a fresh per-head fetch (cache miss). Mirrors the proven setKnownAgents precedent (commit 352b9dd). |
