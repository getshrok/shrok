<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HA (untrusted network client) → Shrok `/v1` | HA presents a Bearer token over the inbound path; Shrok's `/v1` router is the auth gate. |
| Reverse proxy (Apache) → Shrok | During SC2 the bypass deliberately removes Apache Basic auth from `/v1/`, exposing the path publicly until reverted. |
| Operator → `.env` / config.json / Apache vhost (root) | The operator handles a long-lived HA token and an invented inbound key, and makes a sudo vhost edit. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-04 | Elevation of Privilege / Spoofing | Apache `/v1/` AuthType-None bypass left live as a standing public unauthenticated surface | mitigate (BLOCKING) | D-05 apply→verify→**revert**: Task 3's resume-signal requires the revert + passing post-revert configtest before the plan advances. The trailing-slash `<Location "/v1/">` scopes the exemption. Shrok's own bearer check (`HA_INBOUND_API_KEY`) is the real gate and stays active throughout — the curl proves it returns a JSON 401 to unauthenticated requests even while the bypass is applied. |
| T-43-05 | Information Disclosure | HA long-lived token (`HA_ACCESS_TOKEN`) + inbound key (`HA_INBOUND_API_KEY`) handled during rig-up | mitigate | Tokens live only in `~/.shrok/workspace/.env` (ENV_KEY_ALLOWLIST), never committed. `HA_ACCESS_TOKEN` is already in Shrok's log-redaction set (Phase 42 D-05) — existing mitigation, not new work. 43-VERIFICATION.md MUST record outcomes only, never real token values. |
| T-43-06 | Tampering / Denial of Service | Reviving the wrong `~/jarvis-2` containers (full 9-service stack) | accept (operational, low) | Pitfall 1 mitigation baked into Task 1: start ONLY `homeassistant wyoming-whisper wyoming-piper`. Worst case is wasted memory on the operator's own box; no product impact. |
| T-43-07 | Tampering | npm/pip/cargo installs | accept | This plan installs no packages (live test + ledger only); no supply-chain surface. |

T-43-04 is the one threat at `high` for this phase. It is mitigated to acceptable by the blocking revert gate in Task 3 (the plan cannot complete with the bypass still live). All others are at or below `high` and documented-and-accepted.
</threat_model>
