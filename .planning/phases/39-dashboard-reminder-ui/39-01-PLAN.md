## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dashboard browser → POST/PATCH /api/schedules | Untrusted JSON body crosses here; requiresAck/nagIntervalMinutes/startAt are user-controlled and persisted |
| direct API client → PATCH /api/schedules/:id | A non-browser client can send a partial body (e.g. nagIntervalMinutes only, requiresAck omitted) that the edit modal never produces |
| agent (LLM) → create_reminder tool | Tool input arrives from the model; nag slots are user-influenced via conversation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-01 | Tampering | POST /api/schedules nagIntervalMinutes | mitigate | Backend re-validates numeric range 1 ≤ nag ≤ 43200 independent of the client (D-04 source-of-truth); reject non-number with nagNum=0 coupling path |
| T-39-02 | Tampering | POST /api/schedules ack↔nag coupling | mitigate | Reject requiresAck:true+nag=0 and nag>0+requiresAck≠true with 400; mirrors the tool idiom so client and server cannot diverge |
| T-39-03 | Tampering | POST /api/schedules startAt | mitigate | Backend parses startAt, rejects NaN and `<= now` with 400 independent of the client D-09 check — prevents a surprise immediate-fire/backfill via a forged past date |
| T-39-04 | Tampering | PATCH /api/schedules ackPending/nextRun | mitigate | D-12 transition is computed server-side in the route (ackPending cleared + nextRun recomputed via nextRunAfter); the client cannot inject an arbitrary nag-advanced nextRun through the ack-off path |
| T-39-09 | Tampering | PATCH /api/schedules standalone nagIntervalMinutes (requiresAck absent) | mitigate | Direct-API PATCH `{ nagIntervalMinutes: 0 }` on a stored requiresAck:true reminder is rejected 400 by reading the existing row's requiresAck (D-04 source-of-truth) — a forged partial patch cannot strand a nagging reminder with no nag interval |
| T-39-05 | Information Disclosure | dashboard auth boundary | accept | All handlers stay behind the existing requireAuth middleware; no new endpoints, no auth surface change — boundary unchanged |
| T-39-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase (RESEARCH Package Legitimacy Audit: none new); nothing to verify |
