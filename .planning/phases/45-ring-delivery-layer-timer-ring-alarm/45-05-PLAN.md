## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted RingState (disk, survives crash) → startup media_stop | Records written by a prior (possibly crashed) process drive which players are stopped |
| voice "stop" turn → head ring_device(stop) | User dismiss crosses the head tool surface into HA media_stop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-05-DOS | DoS (audio interruption) | startup cleanup | mitigate | RING-11: cleanup iterates ONLY `ringStore.list().filter(headId)` and stops exactly those mediaPlayerEntityIds — never a blind stop-all that would interrupt unrelated playback (Voice PE used as a speaker). Acceptance check confirms no unconditional stop-all |
| T-45-05-BOOT | DoS (boot hang) | media_stop in cleanup when HA offline | mitigate | Pitfall 5: cleanup is fire-and-forget (no await); the RingState record is deleted regardless of stop success so a crashed-then-offline-HA boot does not hang startup |
| T-45-05-DISMISS | (functional, RING-02) | head ring_device(stop) | mitigate | ringRunner threaded to HeadToolExecutor so the dismiss turn actually reaches RingRunner.stop → media_stop + light.turn_off + state delete within one poll cycle |
| T-45-05-TOK | Information Disclosure | cleanup media_stop call | mitigate | Cleanup reuses the runner's token-safe HA REST path (Plan 02 D-05) — no token in logs/errors |
</threat_model>
