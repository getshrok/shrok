<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /apps/:slug routes | Untrusted `:slug` path param crosses into discovery/loadApp; must be guarded against traversal and reserved-name collision. |
| /apps/_pkg/* → package files | Static reads of fixed package files; must expose no arbitrary-file param. |
| app module get()/action() → host route | A throwing app must be contained to its own response. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-03-TRAVERSAL | Information Disclosure | GET/POST /:slug routes | mitigate | loadApp applies SLUG_RE + reserved `_`-prefix guard before any path.join (Plan 02); an escaping slug yields 404, never a read outside appsDir. |
| T-55-03-PKGFILE | Information Disclosure | /_pkg/* routes | mitigate | `/_pkg/*` are LITERAL routes mapping to four fixed package files — no `:file` param, no caller-controlled path, so no arbitrary-file read; pkgDir is module-relative, not caller-supplied. |
| T-55-03-SHADOW | Spoofing | route ordering | mitigate | The `_pkg`/`_skill.md`/`/` literal routes are registered before the `:slug` param routes AND discovery rejects `_`-prefixed slugs, so a malicious app folder named `_pkg` cannot shadow the package routes. |
| T-55-03-CRASH | Denial of Service | get()/action() request handlers | mitigate | Every app-data route wraps loadApp + get/action in try/catch returning the `{ ok:false, errors:[{code:"uncaught_exception"}] }` envelope; a throwing app returns 500 locally while other apps keep serving (D-09 → APPSRV-04). |
| T-55-03-AUTH | Spoofing / Information Disclosure | page/api/action routes | mitigate | `requireAuth` gates the three app-data routes; apps inherit the dashboard session boundary (D-08). Full CSRF + mount-order handling is Plan 04. |
</threat_model>
