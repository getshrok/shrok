## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| schedule row → runner dispatch | A `kind:'script'` row's `taskName` (slug) selects which sensor script runs. The slug → path mapping is centralized in the concrete SensorRunner; runner.ts (Plan 01) re-validates the slug. |
| scheduler tick → model loop | The script branch must NEVER enqueue a QueueEvent — that is the hard SENSOR-06 boundary keeping sensors model-free. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-05 | Elevation of Privilege | script dispatch leaking into the activation/model loop | mitigate | The `kind:'script'` branch calls only `sensorRunner.run` (fire-and-forget) and explicitly does NOT call `queueStore.enqueue`; a test pins `enqueue` is not called (Task 2, SENSOR-06). Sensor stdout never becomes an executable model instruction — it only lands in a file scanned later as plain context. |
| T-48-06 | Tampering | slug → script path | mitigate | Path mapping centralized in the concrete SensorRunner; the slug guard in runner.ts (Plan 01, T-48-01) rejects traversal before any path use. |
| T-48-07 | Denial of Service | one-time script schedule re-firing every tick | mitigate | Branch sets `enqueued = true` so the existing one-time-disable path runs (Pitfall 1); test pins `update(enabled:false)` is called for a one-time script schedule. |
</threat_model>
