  <name>Task 1: Create the pure resolveAllowlist helper with exhaustive tri-state tests</name>
  <files>src/sub-agents/tool-access.ts, src/sub-agents/tool-access.test.ts</files>
  <behavior>
    Type contract (TOOLCFG-07): an allowlist value is `null` (= all tools) or `string[]` (= only those). The per-head override adds a third state — ABSENT (inherit). Model "absent" as the JS value `undefined` at the function boundary (the Zod `.optional()` field is `T | undefined` when read), and "all"/"subset" as `null`/`string[]`.

    `resolveAllowlist(perHeadOverride: string[] | null | undefined, globalDefault: string[] | null | undefined): string[] | null`
    - Resolution order: if `perHeadOverride !== undefined` → use it (null = all, [] / [array] = that subset). Else if `globalDefault !== undefined` → use it. Else → `null` (all tools).
    - Returns `null` for "all" and a `string[]` for a subset. An empty array stays an empty array (subset of zero — distinct from null).

    9 unit tests = override ∈ {undefined, null, ['a','b']} × default ∈ {undefined, null, ['x']}:
    - override=undefined,default=undefined → null
    - override=undefined,default=null → null
    - override=undefined,default=['x'] → ['x']
    - override=null,default=undefined → null
    - override=null,default=null → null
    - override=null,default=['x'] → null   (override null wins — "all" beats global subset)
    - override=['a','b'],default=undefined → ['a','b']
    - override=['a','b'],default=null → ['a','b']
    - override=['a','b'],default=['x'] → ['a','b']   (override subset wins)
    Plus: override=[] (empty subset),default=['x'] → [] (empty array, NOT null — proves "everything off" is representable and distinct from inherit/all).
  </behavior>
