Build the backend API surface and the dashboard TypeScript DTO/client layer for the two global defaults and the two per-head overrides. This is the data contract the UI plan (46-04) renders against. No React components here. The tricky bit is preserving the tri-state across JSON: PATCH must distinguish "field omitted from body" (inherit — delete the config key) from "field sent as null" (all) from "field sent as array" (subset).

Purpose: A clean, tri-state-faithful API and DTO layer lets the UI plan be pure presentation. Splitting it out also keeps this plan parallel with the enforcement plan (46-02) — disjoint files.
Output: /api/tools widened; /api/settings GET+PUT for globals; /api/heads PATCH for overrides; updated heads.test.ts; HeadDTO/SettingsData DTOs + api.ts client methods.
</objective>

  - Field ABSENT from request body → leave the config key as-is (no change for that field).
  - Field present and `=== null` → set the config key to null (all tools).
  - Field present and an array of strings → set the config key to that array (subset).
  - There must also be a way to RESET to inherit: when the field is present and `=== '__inherit__'` (a sentinel string the UI sends to mean "delete the key"), `delete head.headToolsOverride`. (Choose this sentinel because JSON cannot distinguish "key absent in body" cleanly through Express body parsing in a PATCH that may send other fields — the explicit sentinel makes intent unambiguous. Document it in a comment.)
